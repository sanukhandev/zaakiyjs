# @zaakiyjs/image

Optimize **local** images during Node/Vite builds into responsive WebP/AVIF assets with an accessible JPEG/PNG fallback. Browser imports provide metadata and native picture rendering; only the Node export performs image processing.

> **Availability:** Implemented source package on draft production-hardening PR #61. Not independently published or production certified. Unlike Next.js, this initial implementation does not optimize remote URLs on demand.

## Key capabilities

- Configurable responsive widths, target quality and modern WebP/AVIF codecs.
- Fixed intrinsic width and height to reserve layout space.
- Lazy loading by default, optional eager loading and fetch priority for hero/LCP images.
- Optional tiny WebP blur-data URL exposed as metadata.
- SHA-256 content-addressed asset filenames, deterministic sorted manifest, verified output reuse.
- Local-root path and symlink containment; no remote fetch, SSRF, arbitrary user upload processing or runtime codecs.
- Explicit pixel/file size, formats, width and quality budgets.

## Build usage (Node)

~~~ts
import sharp from "sharp";
import { createSharpProcessor, optimizeLocalImages } from "@zaakiyjs/image/node";

const result = await optimizeLocalImages({
  inputRoot: "./public/photos",
  outputDir: "./public/_zaakiy/images",
  processor: createSharpProcessor(sharp, "sharp-0.35.5"),
  images: [{
    id: "hero",
    file: "home.jpg",
    widths: [320, 640, 960, 1280],
    formats: ["webp", "avif"],
    quality: 75,
    placeholder: true
  }]
});
// Save result.manifest.images to a generated trusted module or JSON asset.
~~~

Sharp is a consumer-owned, pinned **build dependency**, not a browser import. Use a local project lockfile and install it in your build environment. This package never downloads or transforms remote images.

## Browser usage

~~~ts
import { createPicture, getImageProps } from "@zaakiyjs/image";

// image is the descriptor generated by the Node build step.
const element = createPicture(document, image, {
  alt: "A descriptive hero photograph",
  sizes: "(max-width: 768px) 100vw, 50vw",
  priority: true
});
document.getElementById("hero")?.append(element);
const props = getImageProps(image, { alt: "A descriptive hero photograph" });
~~~

The native DOM helper creates a real picture element with AVIF and WebP source sets and an img fallback. There is no React/Vue runtime and no virtual DOM. The TypeScript compiler does **not yet** provide a fully automatic Image TSX element or object-prop spreading; use the native helper or pass compiler-supported literal attributes.

## SSR/SSG usage

~~~ts
import { renderPictureHtml } from "@zaakiyjs/image";
const html = renderPictureHtml(image, {
  alt: "An editorial photograph",
  sizes: "100vw"
});
~~~

All text attributes are escaped; only use the generated output inside a trusted server template. Never insert arbitrary user HTML into an unsafe sink.

## Security, quality and migration

Supported inputs: JPEG, PNG, WebP, AVIF raster files; no SVG, GIF, animated/multipage images or remote URLs. Source files must reside within a validated local realpath root; symlink escapes and path traversal are rejected. Limits include 20 MiB source/variant, 40 megapixels, at most 8 widths and quality 30–90. Files are output-hashed, so encoder upgrades can generate new URLs.

The manifest is an output of a trusted build, not a request-time image proxy. The current implementation reads and encodes each configured width/format; there is no cross-run encode cache. A production CDN should serve the immutable outputs with appropriate caching headers and MIME types.

## Benchmark and verification

See the E9 Native Image Optimization CI workflow and benchmark artifacts. The fixture records original JPEG byte size versus selected mobile/tablet/desktop variants, each with decoded dimensions and SHA-256 verification, plus encoding p50/p95 across repeated full builds. Asset transfer savings are not the same as total generated disk size, LCP improvement or faster-than-Next.js performance.
