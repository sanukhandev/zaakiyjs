# Contract 11 — P2 native motion and presence (proposed v1)

> **Status: contract-only; not implemented.** Owner: future \`@zaakiyjs/motion\`. See [ADR 0007](../adr/0007-p2-ui-contract-boundaries.md), [Styles/Motion architecture](../architecture/styles-and-motion.md), and [issue #37](https://github.com/sanukhandev/zaakiyjs/issues/37).

## Dependency and execution policy

Prefer CSS transitions/keyframes generated by \`styles\`; use native Web Animations API (WAAPI) only for genuinely interactive or coordinated effects. The browser motion package may import **public** Core owner or DOM binding types; it must not depend on UI, Router, compiler, Vite, Node, global timers/Promise patches or a mandatory animation framework. Tree shaking and a CSS-only fallback must remain practical; SSR import must not touch \`window\`, \`document\`, \`Element\`, \`matchMedia\` or \`CSS\` at module evaluation.

## Reserved public types

~~~ts
import type { OwnerScope } from "@zaakiyjs/core";
import type { ReadonlySignal } from "@zaakiyjs/signals";

export type MotionPhase = "idle" | "running" | "finished" | "cancelled";
export type MotionEndReason =
  | "completed" | "aborted" | "owner-disposed" | "superseded"
  | "reduced-motion" | "unsupported";
export interface MotionResult {
  readonly reason: MotionEndReason;
  readonly phase: "finished" | "cancelled";
}
export interface MotionHandle {
  readonly phase: ReadonlySignal<MotionPhase>;
  readonly finished: Promise<MotionResult>; // settles once; never unhandled
  cancel(reason?: MotionEndReason): void;
  dispose(): void;
}
export type ReducedMotionPolicy = "respect" | "always" | "never";
export interface MotionOptions {
  readonly owner: OwnerScope;
  readonly element: Element;
  readonly keyframes: Keyframe[] | PropertyIndexedKeyframes;
  readonly timing: KeyframeAnimationOptions;
  readonly signal?: AbortSignal;
  readonly reducedMotion?: ReducedMotionPolicy; // defaults to "respect"
}
export type PresencePhase = "entering" | "present" | "exiting" | "exited";
export interface PresenceController {
  readonly phase: ReadonlySignal<PresencePhase>;
  enter(): MotionHandle;
  exit(signal?: AbortSignal): Promise<MotionResult>;
  dispose(): void;
}
export interface PresenceOptions {
  readonly owner: OwnerScope;
  readonly element: Element;
  readonly enter?: Readonly<Pick<MotionOptions, "keyframes" | "timing">>;
  readonly exit?: Readonly<Pick<MotionOptions, "keyframes" | "timing">>;
  readonly reducedMotion?: ReducedMotionPolicy;
}
~~~

Reserved factories: \`animateOwned(options): MotionHandle\` and \`createPresence(options): PresenceController\`. These are **not currently exported**. Phase is readonly signal state; control methods are explicit operations, not a new scheduler. The optional native AbortSignal is caller-owned; do not abort the caller's controller. A controller uses its own internal abort source for owner disposal/supersession.

## Semantics and races

- \`entering -> present -> exiting -> exited\` describes **visual presence**, not a separate ownership tree. Setup and mount occur under the existing owner; dispose the owner only when the owning render region decides, never have a motion controller unilaterally dispose a parent.
- On parent owner disposal, cancel active WAAPI animations immediately, release observers/RAF/finish listeners and resolve \`finished\` with \`owner-disposed\` or \`aborted\`. No detached element/owner retention. Explicit cancellation/dispose is idempotent; promise settles once, no unhandled rejection on normal cancellation.
- Superseding an exit with a re-entry invalidates the previous completion using a generation token. Stale exit promises must not remove newly active DOM. Restore valid animation styles/fill state; do not leave an element visually hidden after cancellation.
- Default \`respect\` rechecks \`prefers-reduced-motion\` when a run begins and reacts to changes while running; use immediate settled final state for reduced motion, preserving focus and ARIA, without forcing opacity/transform movement. \`never\` is explicit developer opt-out, not a library default.
- Prefer \`transform\` and \`opacity\`; do not read layout synchronously inside reactive render bindings. Limit main-thread work, respect document visibility, avoid uncontrolled scroll observers and clean up AbortSignal listeners.

## Presence boundary: current DOM ABI cannot defer unmount

\`bindConditionalRegion\` and \`bindKeyedRegion\` currently dispose children **before immediate removal**. Calling \`createPresence(...).exit()\` by itself **cannot** extend that owner or retain nodes. Standalone imperative entry/exit works only while the **caller keeps the native node mounted**. Exit-before-remove on \`<Show>\`/\`<For>\` requires a reviewed **exit-aware DOM region protocol** under issue #37, with a forced immediate disposal path on parent teardown. Until then, do not claim declarative \`<Presence>\` or animated keyed removal support.

## Optional layout and advanced motion

Proposed opt-in \`LayoutTransitionOptions\` may capture before/after \`DOMRectReadOnly\` from explicitly scheduled animation frames, then apply FLIP transforms without changing logical/physical owner. Layout/shared-element/view transitions and gestures are deferred, separately feature-detected, and must have safe no-animation fallback. No built-in mutation observer that continuously measures every node. No mandatory Router dependency; route integrations are adapters outside this package.

## Acceptance and compatibility gates

Test WAAPI and CSS fallback; aborted/finished/superseded races; rapid re-entry; owner disposal during animation; rejected/unsupported animation APIs; reduced-motion toggles; no focus loss, stale styles, extra DOM mutations or leaked listeners; deterministic CSS emission and browser-target fallback in Chromium/Firefox/WebKit. Browser imports in Node/SSR contexts must be side-effect-free. No runtime changes or releases in P2-00.
