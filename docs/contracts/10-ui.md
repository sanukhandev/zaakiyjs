# Contract 10 — P2 typed UI components and visual recipes (proposed v1)

> **Status: contract-only; not implemented.** Owner: future \`@zaakiyjs/ui\`. Source contracts are bounded by the **current compiler**. See [ADR 0007](../adr/0007-p2-ui-contract-boundaries.md), [Styles](06-styles.md) and [issue #37](https://github.com/sanukhandev/zaakiyjs/issues/37).

## Responsibilities and package direction

\`ui\` owns visual TSX components, semantic brand token usage, class recipes, variants and typed component event props. \`ui-primitives\` owns unstyled focus/overlay/portal behavior. \`styles\` owns deterministic token generation and recipe conventions; browser UI modules must **not import the Node-oriented styles compiler**. \`motion\` is a peer-optional enhancement with CSS-only/no-animation operation as the default. Components must render compiled native HTML/SVG and never require a JSX runtime or virtual DOM.

A component is an owner-initialized synchronous function; it does **not rerender as a function** on signal changes. Use native semantic elements (\`button\`, \`input\`, \`dialog\`, etc.), native event contracts, caller-supplied callbacks and owner cleanup. No ViewModel or domain service requirement for presentational components.

## Reserved public types

~~~ts
import type { ReadonlySignal } from "@zaakiyjs/signals";
import type { ViewNode } from "@zaakiyjs/core";

export type UiSize = "sm" | "md" | "lg";
export type UiTone = "primary" | "neutral" | "danger";
export type UiAppearance = "solid" | "outline" | "ghost";
export interface UiActionDetail { readonly originalEvent: MouseEvent }
export type UiAction = (detail: UiActionDetail) => void;

export interface UiBaseProps {
  readonly id?: string;
  readonly class?: string; // statically extractable only in the current compiler
  readonly disabled?: boolean;
  readonly "aria-label"?: string;
}
export interface ButtonProps extends UiBaseProps {
  readonly label: string;
  readonly type?: "button" | "submit" | "reset";
  readonly tone?: UiTone;
  readonly appearance?: UiAppearance;
  readonly size?: UiSize;
  readonly onPress?: UiAction;
}
export type UiComponent<Props extends object> =
  (props: Readonly<Props>) => ViewNode;

export interface SelectionChangeDetail {
  readonly reason: "pointer" | "keyboard" | "programmatic";
  readonly originalEvent?: Event;
}
export type UiControlledValue<T> =
  | { readonly value: ReadonlySignal<T>; readonly defaultValue?: never;
      readonly onValueChange: (next: T, detail: SelectionChangeDetail) => void }
  | { readonly value?: never; readonly defaultValue?: T;
      readonly onValueChange?: (next: T, detail: SelectionChangeDetail) => void };
~~~

These types are design agreements; do **not** add stub packages or exports in P2-00. Native JSX \`onClick\` receives \`MouseEvent\`; an \`onPress\` component prop is a semantic component callback, **not** an unrecognized global event. Its implementation should derive keyboard activation from native button click, avoiding duplicate Enter/Space firing. Ensure \`type="button"\` is the default for non-submit actions.

## Brands and CSS variants

- Use existing \`@zaakiyjs/styles\` brand categories: colors, spacing, typography, radii, shadows, breakpoints, appearance and motion. Semantic tokens (e.g. primary, foreground, surface, danger, border, focus ring) map to scoped \`--z-*\` custom properties; no hard-coded palette shared across brands.
- Follow existing \`defineRecipe\`, \`RecipeDefinition\`, and \`uniqueClasses\` semantics: deterministic base, named variants and compound variants; first-occurrence class order. Recipe evaluation is pure. Do not invent a second class merging/CSS generator implementation in UI.
- Current compiler extracts **literal native JSX classes**; it does not safely lower arbitrary runtime class expressions, reactive class/style/attributes or style object props. A runtime recipe invocation **is not proof CSS was extracted**. Ship only compiler-verifiable literal classes or approved pre-generated/safelisted CSS with a **separately supported** safe binding strategy; otherwise fail at build time.
- \`class\` is an explicit override for **already-generated safe styles**, not a backdoor for arbitrary utility creation. Avoid stripping caller-provided focus, disability, high-contrast or reduced-motion classes. CSS variables, recipe token names and scoped brand declarations must remain CSP compatible; no runtime style tag injection.
- Visual variants and accessible state must not diverge. \`aria-disabled\` is not a substitute for the native \`disabled\` property on form controls; preserve required contrast, focus indicator and dark-mode semantics.

## Supported composition versus deferred syntax

**Currently compiler-supported native TSX:** one native element application root, native nested elements, literal classes, statically typed native event attributes, restricted \`<Show>\` and \`<For>\` (including ADR 0006's nested keyed native fragments), and component calls with **explicit, non-JSX props**. Component functions may return a single supported native JSX root; components initialize once per owner.

A viable flat composition has a native host and sibling components, with data/actions passed as explicit typed props:

~~~tsx
function Page() {
  return <main>
    <Button label="Save" onPress={save} />
    <p>Changes are saved only when confirmed.</p>
  </main>;
}
~~~

**Unsupported now:** \`<Dialog><button>Open</button></Dialog>\` (component children, \`ZC2102\`), JSX inside a named slot prop (\`ZC2108\`), \`<Button {...props} />\` (\`ZC1002\`), native \`ref\` (\`ZC1003\`), and reactive/dynamic class or inline style bindings (\`ZC2203\`/\`ZC2204\`). A JSX type being accepted does not imply the compiler lowers it. UI authors **must not** silently substitute a JSX interpreter, hand-wire compiler internals or patch DOM emitted by another owner.

**Planned slot contract (not currently executable):** native children under a component are lowered by Compiler to a lazy, owner-scoped **native-node factory**, mounted once and disposed with its call-site owner. Their source/IR/DOM ABI and portal relocation rules require a coordinated issue #37 review; do not represent slots as runtime \`JSX.Element\` objects. Passing JSX in props and implicit prop spreads are not included by default.

## Accessibility and test gates

Before publishing components: strict prop/event type fixtures; actual compiled app Counter/dialog/tabs/listbox examples; native focus and tab order; keyboard/RTL and inert/escape behavior from primitives; ARIA label/description relationships; controlled/uncontrolled behavior; form integration; stable keyed focus; dark/high contrast and reduced-motion; CSS deterministic extraction and recipe variant coverage. Verify zero UI import-time DOM side effects, zero Node/compiler/runtime CSS injection dependencies, no stale effects and no new browser AI bytes. No current runtime or version is changed by this contract.
